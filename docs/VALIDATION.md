### S2 Ocean modifier

- **Several Ocean modifiers on one object are allowed.** A second modifier in `DISPLACE` mode adds its own spectrum to the
  generated grid. Test `test_stacked_layers_add_in_quadrature`. This replaced the planned UV-sampling composite group;
  `engines/spectral/layers.py` is 20 lines.
- **Grid size:** resolution `N` gives an `N x N` cell grid, `(N^2 + 1)^2` vertices (N = 6 gives 37 x 37 vertices).
  Viewport evaluation uses `viewport_resolution`, renders use `resolution`. Calibration and baking therefore set
  `viewport_resolution = resolution` temporarily.
- **Rest grid:** vertex x = `(u - 0.5) * spatial_size * size` exactly (choppiness 0), UV spans 0 to 1; vertex order is x-fastest.
  `bindings.ocean.evaluate` and `engines/spectral/query.py` rely on it.
- **Amplitude is exactly linear in `wave_scale`** (std at scale 0.5, 1, 2 = 0.132, 0.265, 0.530). Calibration is analytic.
- **Seed-to-seed variability is large.** Hs of single seeds on a 100 to 400 m tile differs by about 10 to 25 percent at equal
  `wave_scale`, and a single seed's Hs fluctuates over time by several percent. The first calibration (3 seeds, scale fit)
  gave held-out errors up to 24 percent. The shipped method picks the seed closest to the ensemble and fits that seed
  (`engines/spectral/calibrate.py`); see `VALIDATION.md` for per-preset spread.
- **`fetch_jonswap` units:** not determined. No preset sets it except through the default.
- Choppiness shifts vertices horizontally (max 1.12 m at choppiness 1.5, wind 10 m/s, 100 m tile).
  `GridHeightQuery` inverts the shift with three fixed-point passes.

### S5 Whitewater data path

- `particle_systems[i].particles.foreach_get("location", buf)` on the evaluated object: 200k particles in about 4 ms.
- Not tested: reading Mantaflow secondary particle systems (needs a bake).

### S6 Heightfield speed

Single NumPy thread, one core: 340, 68, 14 and 2.8 steps/s at 128, 256, 512 and 1024 squared in the final run (177, 34, 8.1 and 1.8 in an earlier run on the same shared machine). NumPy does not use more
cores for these array operations, so the 8-core budget is unreachable without a compiled core. Practical limit with
NumPy: about 512 x 512 for an interactive bake. All shipped heightfield presets are 100 x 100 or smaller.

### S8 Headless Mantaflow and bakes

- `bpy.ops.fluid` has `bake_all`, `bake_data`, `bake_guides`, `bake_mesh`, `bake_noise`, `bake_particles`, `free_*`, `pause_bake`.
- **The desktop build bakes, the PyPI `bpy` wheel aborts.** In desktop Blender 5.2.1 (`--background`) a `dam_break`
  domain bakes 40 frames in 23 to 29 s and writes 160 cache files, and the liquid mesh advances frame by frame. The same
  domain in the PyPI `bpy` module aborts the interpreter (`Manta::Error: can't clean grid cache`), so the abort is a
  property of that wheel, not of Blender. Consequence: the fluid tests still inspect configuration only, but real bakes
  and the fluid validation runs live in the desktop build (`tools/fluid_validation.py`).
- `bpy.ops.object.ocean_bake` returns FINISHED headless but writes nothing (it is a background job). FlowFX bakes the surface
  itself (`engines/spectral/bake.py`), which also exposes horizontal displacement.
- **The surface emission band inflates a flow object.** `add_flow` set Blender's default `surface_distance` of 1.5 m on every
  flow object. A geometry flow (the dam-break reservoir) therefore filled 0.15 m beyond the block on every side, 30.8 m3
  instead of 24.0 m3, and the river inflow emitted a 3 m deep sheet instead of the designed 0.5 m. The BLOCK, SOURCE and
  SINK roles now ask for a zero emission band (`engines/fluid/roles.py`).
- The liquid mesh does not contain spray or foam particles: a bake with both switched off produced an identical mesh.

### S10 Secondary particle toggles

`use_spray_particles`, `use_foam_particles` and `use_bubble_particles` behave as **toggles** in 5.2.2: assigning `False`
to a flag that is already `False` turns it on. Reproduced with scripts (`True` twice reads `False`). Workaround in
`engines/fluid/secondary.py`: set only when the value differs, then read back and raise if it still differs. Check whether
5.2.1 behaves the same.

### S11 Ocean dispersion

Median error of the strongest Fourier modes against `omega^2 = g k tanh(k h)`: 0.4 percent (JONSWAP, deep), 0.3 percent
(Shallow Water spectrum, 3 m), but 17 percent (Pierson-Moskowitz low-wavenumber modes) and 7 percent (1.5 m depth). The
Ocean modifier generates standing-wave modes, so phase tracking fails; the temporal spectrum of each mode is used.

### S12 to S14

- Foam (`foam_layer_name`) is a CORNER-domain attribute. `bindings.ocean.read_scalar_attribute` averages corners per vertex.
- A Dynamic Paint canvas needs `bpy.ops.object.modifier_add(type='DYNAMIC_PAINT')` then `bpy.ops.dpaint.type_toggle(type='CANVAS')`;
  setting `ui_type` alone leaves `canvas_settings` as `None`. `surface_type` takes `WAVE`.
- `scene.compositing_node_group` exists; compositor group outputs use `NodeGroupOutput` with interface sockets.
  `CompositorNodeComposite` and `CompositorNodeMixRGB` are gone; `ShaderNodeMix`, `ShaderNodeMath` and `ShaderNodeMapRange` work.
- Materials always have a `node_tree`. Principled sockets: Base Color, Roughness, IOR, Transmission Weight.
- Geometry Nodes inputs: `modifier.properties.inputs.<identifier>.value`.
- Cycles Volume Absorption: `sigma = density * (1 - color)` verified by render at 1 m and 4 m, zero error.
- Cycles caustics properties: scene `caustics_reflective`, `caustics_refractive`; object `is_caustics_caster`, `is_caustics_receiver`;
  light `is_caustics_light`.
